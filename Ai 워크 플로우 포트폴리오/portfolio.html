01 — Vision

기술이 아니라 사람의 문제입니다

AI 도입의 가장 큰 장벽은 기술이 아닙니다. "내 일을 빼앗기는 건 아닌가"라는 불안, 익숙한 방식을 바꿔야 한다는 저항 — 이것을 넘지 못하면 어떤 도구도 정착되지 않습니다.

🎯

제품을 위한 개발

개발을 위한 개발이 아닌, 제품을 위한 개발. 코드는 제품의 수단이지 목적이 아닙니다. 이 관점 전환이 AI 도입의 출발점입니다.

🔄

역할의 수평 확장

개발자의 역할은 "코드를 짜는 사람"에서 "제품을 만드는 사람"으로 확장됩니다. 더 넓은 시야에서 제품 전체를 조망할 수 있게 됩니다.

⚡

직관은 계속 진화한다

수직적 기술력(코딩 스킬)은 AI가 도구로 대체하되, 아키텍처 판단, 설계 직관은 사람만이 가진 핵심 역량입니다. 이 직관은 멈추지 않고 계속 개발해야 합니다.

🤝

개발자 출신의 커뮤니케이션

개발자의 언어를 이해하는 사람이 변화를 리드해야 합니다. 20년 개발 + PD 경력으로, 현장의 저항을 공감하고 설득할 수 있는 커뮤니케이션이 가능합니다.

"AI에게 코딩을 맡기는 것은 개발자를 대체하는 것이 아닙니다.
개발자가 더 높은 곳에서 제품을 바라볼 수 있게 하는 것입니다."
02 — Pipeline

기획이 제품이 되기까지

기획서가 드롭되는 순간부터 PR이 머지되는 순간까지. 사람이 판단하는 지점과 AI가 실행하는 지점이 명확히 구분됩니다.

1
기획 드롭 HUMAN

기획자가 새로운 기획서를 시스템에 등록합니다. 요구사항, 레퍼런스, 우선순위가 포함됩니다.

2
기획 리뷰 HUMAN + AI 🔍 기획 검수 에이전트

기획 검수 에이전트가 구현 가능성, 모순점, 리스크를 사전 검수합니다. 사람은 최종 판단과 방향 결정을 합니다.

💡 4개 페르소나(SYS · PLAN · CON · ART)가 각자의 관점에서 기획을 검토하고 의견을 교차 검증합니다.
3
기획 확정 HUMAN

리뷰를 통과한 기획이 확정됩니다. 이 시점의 확정 기획서가 이후 모든 프로세스의 원본(Source of Truth)이 됩니다.

4
지식 가공 (Knowledge Layer) AI 📊 지식 가공 에이전트

확정된 기획서를 LLM-Wiki와 Graphify로 정제합니다. 비정형 기획 데이터가 구조화된 지식 그래프로 변환되어 AI의 재료가 됩니다.

📊 기획서 → LLM-Wiki(문서 정제) → Graphify(관계 그래프 구축) → Claude가 참조할 수 있는 고신뢰도 지식 기반 완성
5
개발 플랜 생성 AI ⚙️ 개발 에이전트

지식 그래프를 기반으로 Claude가 구현 계획을 수립합니다. 기존 코드베이스와의 정합성, 의존성, 작업 순서를 분석합니다.

6
코드 생성 AI ⚙️ 개발 에이전트

개발 플랜에 따라 AI가 코드를 생성합니다. 지식 그래프에 기반하여 기획 의도에 정확히 부합하는 구현을 만들어냅니다.

7
코드 리뷰 HUMAN + AI 🧪 QA 에이전트

AI가 1차 리뷰(컨벤션, 버그 패턴, 성능)를 수행하고, 사람이 아키텍처 판단과 제품 적합성을 최종 검토합니다.

8
테스트 하네스 (Headless Test) AI — QA Agent

헤드리스 환경에서 QA 에이전트가 자동 테스트를 수행합니다. 하네스는 기능 검증, 회귀 테스트, 성능 프로파일링을 UI 없이 실행하며, 결과를 기반으로 통과/실패를 판정합니다.

🛡️ 하네스의 역할 — 파이프라인의 최종 관문. 코드가 아무리 빠르게 생성되어도 하네스를 통과하지 못하면 PR이 생성되지 않습니다. AI가 만든 코드의 신뢰도를 보장하는 안전장치이자, 전체 파이프라인의 품질 기준선입니다.
9
PR 생성 & 문서화 AI 📝 문서화 에이전트

하네스를 통과한 코드만 PR로 생성됩니다. 테스트 결과, 변경 사항, 기획 대응표가 자동으로 문서화됩니다.

🔧

개발자의 새로운 핵심 업무 — 하네스의 관리와 진화

AI가 코드를 생성하는 시대에, 개발자의 가장 중요한 역할은 이 하네스를 설계하고, 관리하고, 업그레이드하는 것입니다. 하네스의 품질이 곧 파이프라인의 신뢰도이며, 제품의 품질입니다. 더 정교한 테스트 시나리오, 더 빠른 실행 속도, 더 넓은 커버리지 — 이것이 개발자의 직관과 경험이 발휘되는 지점입니다.

04 — KPI Innovation

AI 기반 개발이 가능하게 하는 KPI의 혁신

AI가 코드를 생성하고, 하네스가 품질을 보증하는 표준화된 파이프라인에서는 기존에 측정하기 어려웠던 개발 생산성을 정량적으로 측정할 수 있게 됩니다.

📈

순수 코드 생산량 (Net Code Output)

코드 생산량 − 삭제량 (리팩토링 등) = 순수 생산량

AI가 표준화된 코드를 생성하기 때문에, 개발자별 코딩 스타일 차이가 사라집니다. 이로써 코드 생산량에서 리팩토링·삭제량을 제외한 순수 코드 생산량이 개발자의 실질적 기여도를 측정하는 공정한 지표가 됩니다.

🔄

왜 가능해지는가

기존에는 개발자마다 코딩 스타일, 설계 방식, 코드 밀도가 달라서 단순 라인 수로 생산성을 비교하는 것이 불공정했습니다. AI 기반 표준화된 개발에서는 코드 생성의 일관성이 보장되므로, 생산량 자체가 의미 있는 지표로 전환됩니다.

🎯

개발자가 달성해야 할 것

개발자의 목표는 "좋은 코드를 짜는 것"에서 "더 많은 제품 가치를 만들어내는 것"으로 전환됩니다. 하네스 품질 관리, LLM-Wiki 기여, 기획-코드 정합성 — 이 모든 것이 순수 생산량에 반영됩니다.

05 — About

개발자의 언어로 혁신을 리드합니다

20년간 게임 업계에서 개발자로, 그리고 PD로 일하며 "기술과 제품 사이의 간극"을 직접 경험했습니다.

개발자가 AI 도입을 거부하는 이유를 압니다. 그 저항이 두려움이 아니라 장인 정신에서 오는 것임을 이해합니다. 그래서 저는 "코드를 빼앗는 것"이 아니라 "더 높은 곳에서 제품을 바라볼 수 있게 하는 것"을 이야기합니다.

직접 구축한 AI 워크플로우로 1인 개발 프로젝트를 운영하며, 이 시스템이 실제로 작동함을 증명하고 있습니다.
